Siemens S7-1500 & OT Protocols
Q1: What is the fundamental difference between S7comm (ISO-on-TCP) and Siemens S7-1500 Web API?
Verbatim Defense:
S7comm (RFC 1006 / ISO-on-TCP) operates on TCP port 102. It communicates directly with the PLC firmware communication processor using proprietary binary protocol packets. It addresses memory by raw byte offsets (e.g., DB100,DBD4 or DB21,X0.0). It requires Optimized Block Access to be turned OFF in TIA Portal so that data offsets remain static in physical memory, and the PLC Permit access with PUT/GET communication from remote partner must be explicitly enabled. In contrast, the Siemens Web API operates on TCP port 443 (HTTPS) via JSON-RPC 2.0. It communicates with the CPU internal web server, accesses variables symbolically by tag name, works natively with Optimized Data Blocks, supports TLS encryption, certificate verification, and role-based user access tokens.
Siemens S7-1500 & OT Protocols
Q2: What is Optimized Block Access in Siemens S7-1500, and why does legacy S7comm fail when it is enabled?
Verbatim Defense:
In legacy non-optimized blocks (S7-300/400 style), variables are aligned strictly along static byte boundaries, which creates memory padding and fragmented access times. In S7-1500, Optimized Block Access allows the CPU compiler to automatically arrange variables by data type for optimal 32/64-bit memory bus access, regardless of declaration order. Because variables no longer have fixed physical byte offsets, legacy S7comm drivers (like nodes7 or libnodave) cannot calculate absolute memory pointers and return error 0x8104 (Address invalid). The Siemens Web API and OPC UA solve this because they query the symbolic runtime dictionary compiled into the CPU firmware.

Q7: Compare OPC UA Polling vs. Subscriptions and MonitoredItems on a 51 JPH manufacturing line.
Verbatim Defense:
Polling repeatedly queries the OPC UA server at a fixed frequency, flooding the network and consuming PLC CPU deserializing requests even when machines are static. Subscriptions establish a session with a requested PublishingInterval (e.g. 200ms) and MonitoredItems with a SamplingInterval (e.g. 50ms) and DataChangeFilter (Deadband). On a 51 JPH automotive line, Subscriptions reduce network bandwidth by >80% while ensuring instantaneous sub-second response times for discrete signals like Weld Complete or Safety Fault.

Q8: What is Modbus RTU vs. Modbus TCP, and what is the difference between Function Code 03 and Function Code 04?
Verbatim Defense:
Modbus RTU operates over RS-485/RS-232 serial physical layers, framed with slave address, function code, data payload, and a 2-byte CRC16 checksum with 3.5 character silent delimiters. Modbus TCP encapsulates the Modbus PDU over Ethernet port 502 using a 7-byte MBAP (Modbus Application Protocol) header (Transaction ID, Protocol ID 0, Length, Unit ID) without CRC because Layer 4 TCP provides error checking. Function Code 03 (Read Holding Registers) reads read/write 16-bit registers (40001 series) used for setpoints and operational variables. Function Code 04 (Read Input Registers) reads read-only 16-bit registers (30001 series) used for physical sensor measurements, active power, and analog inputs.

Q9: How do you handle 32-bit floating point byte-swapping (Endianness) across different field meters?
Verbatim Defense:
Modbus registers are strictly 16-bit. A 32-bit float requires two registers (4 bytes). Q11: What is Profinet IO, and how does it differ from standard TCP/IP communication?
Verbatim Defense:

Q22: Explain MQTT Quality of Service (QoS) levels: QoS 0, QoS 1, and QoS 2. Which do you use for machine telemetry vs. recipe dispatch?
Verbatim Defense:
1) QoS 0 (At most once / Fire and Forget): Message is sent with no acknowledgment; packets may be dropped during network congestion. Used for high-frequency analog continuous telemetry (e.g. instantaneous motor RPM, vibration, ambient temperature) where the next value arrives in 200ms anyway. 2) QoS 1 (At least once): Message is resent until a PUBACK is received from the broker; guarantees delivery but duplicates are possible. Used for shift production counters, hourly energy totals, and alarm state changes. 3) QoS 2 (Exactly once): Uses a 4-step cryptographic handshake (PUBLISH -> PUBREC -> PUBREL -> PUBCOMP) guaranteeing delivery without duplicates. Used for critical recipe parameters, part marriage authorizations, and robotic spot-weld schedules where duplicate writes could damage tooling.

Q35: What is the difference between Inductive, Capacitive, and Photoelectric proximity sensors?

Q36: What is NPN vs. PNP sensor wiring (Sinking vs. Sourcing)? Which is standard in Siemens European automation?
Verbatim Defense:

Q40: What is the difference between 4-20mA current loop and 0-10V analog voltage signals?
Verbatim Defense:
0-10V signals transmit analog measurements as a voltage level across a high-impedance input. Because long factory cable runs have wire resistance, voltage drops occur, corrupting the reading. Q76: Why use WebSockets (RFC 6455) instead of HTTP REST polling for plant-floor HMI screens?
Verbatim Defense:
HTTP REST operates on a request-response model requiring a complete TCP handshake (SYN, SYN-ACK, ACK) and heavy HTTP header parsing for every individual poll.
